# 择时模块（/timing）改造任务表

> 来源：2026-09-24 两轮职业股民视角评审（我方 + 另一 AI）合并清单，关键论断已用当日 `timing_data.json`（19:23 生成）实测验证。
> 目标：从"回测展示器"升级为"交易决策工具"——回答**现在、这个月、用哪招、仓位几成、错了亏多少**。

## 数据链路现状（改动定位用）

```
~/.hermes/scripts/style_compass_cron.py  (周一 cron / 手动刷新)
  └─ gen_timing_data.py  (236行, 离线聚合)
       输入: events.json(178MB, 全量信号含 T5/T10/T20/lim)
             market_regime/stage_win.json (只有胜率, 无 n/avg)
             market_regime/staged.json    (逐月 regime 全历史, 含 gap/vol/breadth)
             kline_10y.parquet            (当前只读 close 列)
       输出: timing_data.json
  └─ vr/timing.py → /api/market/timing  (FastAPI 透传)
  └─ frontend/src/pages/TimingOverview.tsx / TimingStrategy.tsx
```

**两个降低排期的关键事实：**
1. `events.json` 每条信号**已带 T5/T10/T20 三个持有期收益** → 持有期衰减曲线几乎零成本，不用重跑回测。
2. `staged.json` 有**逐月 regime 全历史** → "进入当前阶段几个月、上月什么阶段、K线阶段色带"都只是读取，不用新建模。

**已确认的口径风险：** T10 收益**未扣任何成本**（生成脚本无费用字段），两家评审的高风险未知项已坐实。

- **第一批（P0 全量 + P1-1/P1-2）**：都是"字段已在数据里、只差聚合和展示"的活，gen_timing_data.py 一个脚本改完 + 两个前端页面，是投入产出比最高的一刀。做完页面就从"看历史"变成"告诉我下周一买什么"。

### R2【中】推荐灯号只看胜率不看期望值，"降仓"告警被绕过

实测当前缩量阶段：low_reversal 拿唯一"优先"灯（阶段胜率 50.8%、近3月 51.0%），但其缩量 `avg_net` 仅 **+0.04%**、超额随机基线（47.96%）仅 **+2.8pct**——edge 在噪声范围内，"优先"却给出"可以上"的行动暗示，且 `all_below_half` 降仓告警因此失效。

- 改动点（`gen_timing_data.py` recommendation 段）：
  - `prefer` 增加两个条件：当前阶段 `avg_net > 0` **且** 阶段胜率超额随机基线 ≥ 3pct（`stage_win - random_baseline.win >= 0.03`）；
  - `all_below_half` 判定同步改用"有效胜率"（超额基线后仍 ≥50% 才算 ≥50%），或新增 `no_prefer` 字段：无 prefer 灯时前端同样提示"当前阶段无可信赖战法 → 降仓/空仓"；
  - RecTable Caliber 文案同步说明新灯号规则。

### R3【低】cost.note 与 recent.t10 命名矛盾

`cost.note` 写"所有收益字段为税前口径，*_net 为税后"，但 `recent.t10` 实际是**税后**（已扣 COST_RT=0.002，与 events T10 对账差值恰为 0.002）却不叫 `t10_net`。前端表格已标"T+10税后"（用户侧无误），但 JSON 消费方会被 note 误导。

- 改动点（二选一，建议 a）：
  a. note 改为："收益字段默认税前（baseline/stage_stats/decay/hold_curve 的 avg、K线 OHLC）；*_net 为税后；**例外：recent.t10 为税后**"；
